## HTML candidate, NOT production applied

html-evidence.mjs accepts only bounded bytes fetched from exact official JRA accessD URL with one CNAME parameter; rejects credentials/extra parameters, race/date/CNAME mismatch, future/invalid timestamp, non-HTML and obvious secret patterns. No headers, API keys, cookies or environment captured. Secret pattern checks are defense in depth, not comprehensive DLP. It retains original response bytes gzip-compressed, wire SHA256, gzip SHA256 and decoded shift_jis→UTF8 SHA256 (matches v26 decoded-hash convention). Exact-byte replay verifies all hashes and bounded decompression. Source timestamp and 30-day expiry retained independently for repeated observations. Replay returns status_verified=false; it never infers ACTIVE or READY. Fetch-time race DOM contents still need actual validation: CNAME agreement alone does not prove page-body race identity.

Storage proposal: separate jra_evidence_private schema, not to be exposed via Data API. Two RLS/FORCE RLS tables: deduplicated immutable blobs and append-only capture observations. Service_role SELECT/INSERT only; no anon/authenticated access, UPDATE/DELETE/TRUNCATE. Service-only public ingestion RPC SECURITY INVOKER/fixed pg_catalog path, private tables fully qualified. No public download, signed URLs, browser previews or HUB connections. Before deployment verify project exposed-schema configuration and extensions.digest already exists; no extension is installed here. Authorized server/admin can export by capture ID and replay locally; do not return raw HTML through chat/logs or render scripts in a browser. External viewer, if built, must be sandboxed with script disabled.

Limits: 2 MiB raw and compressed per body; 512 MiB compressed payload budget plus PostgreSQL overhead, metadata and indexes (not a hard limit on physical DB size); max100,000 capture events. Shared advisory lock and capacity triggers enforce direct inserts as well as RPC for read-committed transactions. Other isolation levels rejected. Serialized quota/concurrency handling, actual RLS, ACL, SQL compilation and immutable triggers need isolated PostgreSQL tests. DB validates gzip hash; original-wire and decoded hashes verified by trusted client replay, not DB decompression. No claim of DB-certified source authenticity.

Retention: captures expire 30 days after fetch. NOT automatically deleted merely by expiry. Proposed postgres-only maintenance must delete expired observations and then orphan blobs in a separate approved operation; none installed, no cron changed.
