# REBORN 2 | Stage20 prospective evidence retention design v0.1 (research only)
2026-11-27 JST. Parent acceptance 1568a09381601b87a235291e446dfc09ea654833. No production or existing acquisition changes. This is a provider-permission-dependent proposed design, not a deployed or approved collector.

## 1. Rights before capture
A permission receipt specifies authority/provider, approved source and endpoints, permitted manual/automatic acquisition and rate/volume, raw and derived storage, AI processing and cloud/processor destinations, retention/deletion, geographical/tenant restrictions, quotation/publication including private/limited/free/paid HUB, effective interval, revocation and proof. Unknown scope denies the relevant action. Public browsing is not consent for capture/storage/AI/redistribution. Do not collect or enable cron on this design. No paid contract, inquiry send, or bypass. Existing JRA/NAR draft remains unsent. For nonpermitted raw market fields, use a provider-approved source omitting them; otherwise do not acquire the raw source. Any lawfully captured source that incidentally contains market data remains restricted raw-only; extract from an explicit allowlist, never expose market/target outcome to analysis.

## 2. Separate immutable objects
A. Source capture envelope (one capture, never upsert by race):
capture_id, issuer, source_kind, exact request URL and canonical event key, request_started_at_utc, response_finished_at_utc, clock source/uncertainty, HTTP status, allowed source origin and final URL, source-provided version identifier if present, official_published_at_utc nullable with citation and precision, observed_at_utc, response Content-Type, Content-Encoding, charset declared and decoder version. No auth header, cookie, token or personal secrets. Distinguish response entity bytes actually returned by client (possibly transport decompressed) from wire bytes; never claim wire if unavailable. Record hash_input_kind=RESPONSE_ENTITY_BYTES or WIRE_BYTES, exact transformation/transport semantics, sha256 lower-hex, byte_length, media type, immutable object ID/version. Store original bytes before text decode; optional separate decoded UTF-8 hash with explicit distinct input kind/decoder and error policy. No re-encoding substitute, no fabricated bytes, no unlabelled DOM hash. Capture permitted scopes/receipt ID, retention_until, access class and legal disposition. Capture does not prove origin's original publication time. Null remains null.
B. Append-only custody receipt: capture_id, raw object ID/version, raw hash, length, canonical manifest hash (algorithm/version), independently verified time and uncertainty, append-only log index and prior root, external signed checkpoint/attestation and verifier trust configuration. Seal must exist before the selected cutoff; later backdating or a self-signed manifest alone is insufficient. Object versioning alone or DB updated_at is insufficient. Read-back verifies exact bytes and length; independent verification of signature, time, chain and object retention. Hash verifies bytes, not provenance, rights or timestamp.
C. Extraction: extractor code commit and parser version, capture_id + raw hash + hash_input_kind, exact source row locator (DOM path/table/row, or byte range if available; record locator type), source literal and normalized typed values with units, normalization version, parse failures, issuer-scoped native IDs and authentication method. Link horse, race, actual historical runner number, jockey/trainer separately; never join only by name, never reuse target number. Cross-circuit mapping requires independently evidenced native ID pair + stable identity attributes + validity interval + conflicts/revisions. No inferred individual sectionals from race leader. Keep margin lengths vs time and historical class label vs eligibility distinct.
D. Roster and conditions: one version-scoped field manifest listing all registered rows, each ACTIVE/CANCELLED/EXCLUDED/UNKNOWN and native horse ID, source row link, verification basis, count reconciliation, declared post time and version, track/surface/distance/going/weather/course rail/class/weight rule, course effective interval and publication evidence. A capture with unknown active state is held for full-field replay. Roster proof must refer to exactly the same raw hash and version (or an explicitly authenticated same-version separate source). If status source differs, preserve explicit cross-source correspondence and times, no transfer by name/number alone.
E. Correction ledger: source capture versions and parsed versions separate; append supersedes links with official correction publication/observation time, original values retained under rights, reason, changed fields and effective period. Retractions/corrections do not rewrite prior snapshots. Fork/conflict is held. Historical source already seen may be replayed only as known at cutoff, not with later corrections. A later official correction is separately tracked for retrospective research. If rights require deletion, preserve only permitted tombstone/metadata, mark missing and block replay; immutability is not indefinite retention.
F. Replay manifest: target event, explicit analysis_cutoff <= official scheduled start and strictly before actual start if known, immutable checkpoint before cutoff, exact capture/extraction/roster/condition versions, event/row IDs and permission receipt for each observation. Source publication time is separate from proof of observed bytes; if publication is unknown, label OBSERVED_BY_CUTOFF only with trusted contemporaneous capture and seal, do not mark publication verified. Existing REBORN2 formal policy remains held pending separate acceptance of any alternative proof. Capture and sealing upper uncertainty bounds must be <= cutoff; cutoff must be strictly before declared post. A delayed or changed official post time needs authenticated version; no retroactive widening. Historical result events strictly before target and publication or observation <= cutoff; exclude target result and market at extraction, manifest and runtime. No later observation on historical date presented as known at cutoff.
G. Evidence record: issuer, subject_id, event_id, historical_no, exact version, source locator, raw/extraction digest, observation field/unit, observed/published time and confidence, condition applicability, correction reference, rights scope, availability/held/missing reason. Distinct states NATIVE_AUTHENTICATED, STORED_STRUCTURED_WITNESS, STORED_TRANSCRIPTION, LOCATOR_ONLY, UNAVAILABLE; only authorized and validated field values are even eligible for later separately approved research. Missing is UNKNOWN not counter or C. 115 item definitions unchanged, no semantic effect from locator count. Stable root issuer/event/subject/source row/field (same observation across copies and derived EYE not independent); preserve version lineage and no transitive strength inference.

## 3. Proposed transaction sequence (not implemented)
Rights allowlist -> fetch permitted source once -> capture exact bytes -> write non-overwriting restricted object -> independent readback/hash/length -> append custody receipt and obtain trusted checkpoint -> parse version-pinned input -> field/ID/time/units/correction validation -> version-specific roster seal -> create replay manifest -> authorized research validator.
Any error: hold and log reason, no fabricated data or production fallback. Stop on rate limit; honor provider Retry-After and terms, do not retry through alternate routes. No current target output values, ranking or FROZEN are used.
An independent verifier must recompute bytes, signature/checkpoint and source identity, and resolve source permissions; mock flags cannot do this. Separate collector/verifier/analyst roles, private encrypted storage, least privilege and auditable access, raw data unavailable to HUB and source exports denied by default. No raw or sensitive URL secrets in GitHub. Retention must follow provider and legal rights, with documented deletion of raw and derived data where required. Independent backup under same rights with restore to isolated research only; no production restore. Use provider-approved storage and signing service after authorization and cost approval; no vendor assumed or provisioning now.
Recommended first lawful pilot: one future JRA and one future LOCAL race, source and cutoff approved in advance, collect only before cutoff, record corrections separately, independently read back bytes, verify all row links and active states, then separately ask for research admission. No target result read during intake. Keep 118/826 existing formal gates false; prospective design does not authorize any actual race.

## 4. Verification requirements
- Exact byte hash/length, charset and digest domain distinction; raw missing, wrong encoding, regenerated DOM or new page must fail old hash proof.
- Trusted signed/checkpoint time before cutoff; no late seal, timestamp inversion, excessive uncertainty, poststart cutoff or unknown proof. Distinguish observed-only vs official publication verified. Formal research requires accepted proof policy and permission.
- Missing permission for capture/storage/AI/processor, expired/revoked rights, retention breach and public sharing without separate rights fail. Unknown never silently allowed.
- Same-version roster, full and unique IDs/numbers, explicit active state, source row references, correction as-of, class/course effective intervals and event chronology. Cross-issuer link must be authenticated, otherwise hold only affected evidence.
- Reject target result/market anywhere in analyzed payload by schema allowlist and recursive scan; raw is isolated and never passed to analyzer. No source value fabricated from hash/locator.
- Corrections and duplicate roots tested without changing earlier frozen cutoff; distinguish raw proof vs extraction vs analysis. Source signature verification, actual byte hashing, authorization integration and adversarial parser validation are future independent implementation tests, not claimed here.
