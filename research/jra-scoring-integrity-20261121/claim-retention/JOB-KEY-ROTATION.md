# Incident procedure — owner approval required

The retained v27 source declares a static credential at index.ts:6. At line 474 the handler compares the JSON body key with that credential. A match enables the internal branch of a handler using a server-side service client. Two actions (sync_next_month and import_batch) have a separate cron admission path with a state check. Changing the internal secret alone does not disable those actions. The recorded v27 gateway configuration has verify_jwt=false. The current validity and caller population have not been tested. Treat the exposed credential as compromised.

1. Restrict access to the incident transcript, execution logs and old bundles. Inventory callers by function name, action and deployment metadata. Inspect cron definitions only through a redacted projection. Do not print bodies, command text, environment values or replay the exposed credential. Review privileged actions since exposure using timestamps and request IDs.
2. Get operator approval for a coordinated cutover. Prepare a server-only secret using the approved secret manager, provision the new value to authorized internal callers, and disable body logging. Replace the literal comparison with a configured, nonempty secret check; missing configuration must deny internal access. Verify the existing two cron actions separately. Test missing and random invalid keys and an authorized read-only/no-op probe in isolation. Do not use a mutating production action as a credential test.
3. Deploy the reviewed receiver and switch authorized callers in a bounded maintenance window. Remove old secret material from callers and logs according to retention policy. Verify function version and denied/accepted counters without logging request data. Inspect earlier Git history and deployment artifacts in a restricted environment. Redact any further copies.
4. On failure, pause affected internal calls or roll forward with another fresh secret. Never roll back to a bundle accepting the exposed literal. Record operator, version, UTC times and verification outcome only.
