# Isolated submission and evidence boundary

The v39 save tool accepts a caller-authored payload. In candidate-index.ts the authenticated handler checks the active field and passes the submitted runner_history_checked entries to inspectJraFullDepthSave before the deterministic bridge. The attached observer patch snapshots that submission at this boundary. A previously bridged proposal is recorded as actually submitted. The before/after bridge record belongs to the subsequent independent ledger check. This boundary establishes where the numbers enter the service. It cannot identify which client or person made a historical judgment.

Decision specification: preserve each horse number, submitted base, signed numeric evidence effects and cited sources, assessor reason, submitted review rank and score, exact canonical context and payload digests. No conversion of rank into score or grade. Replay declared arithmetic with final-provider/replay-morning.mjs. Hashes bind a supplied snapshot and do not archive its missing contents. A deleted or unavailable context cannot be regenerated from its digest. Existing FROZEN rows cannot retroactively acquire a submission snapshot.

## LIVE capture candidate

jra-live v32 fetchCard → parseCard → jra_live_runners.past_runs is the LIVE source. These histories are embedded in the target race card. The accessS result archive is a separate source. live-card-observer.patch taps the original successful accessD response before decoding, retaining raw bytes after the runner upsert via a default-off server hook. live-evidence.mjs records the race ID, capture/source time, horse ID and canonical run digest. The private context returns the exact selected JSON plus the runner snapshot timestamp in its stripped sidecar. Verification requires unique receipt and parser matches. A content digest identifies the selected JSON within that capture; no archive run ID is created. Flat-history normalization that changes JSON fails closed.

The reader and receipt verifier are server dependencies. Production needs approved private retention, a claim-scoped signed reader and the pinned card parser with the same acquisition options, including any repair inputs. Receipt verification must bind job, context digest, document digest, issuer and lease to the exact read. The test injects these dependencies and uses synthetic bytes. No production store or signer was approved or shown to support this protocol. LIVE evidence remains separate from DB factor proofs and cannot authorize a save.

## Private archive and signing approval

Read-only inventory found zero private Storage buckets and zero JRA-named HTML/document/archive tables in private. Existing live Edge acquisition may supply the bytes once approved. Proposed minimum is one private Postgres table, with a dedicated INSERT-only writer and a separate reader role held solely by the broker. The reader role can read the table, so the broker itself is a trusted boundary. Keep both roles out of PostgREST and never give their credentials to a client. No application role receives UPDATE, DELETE or TRUNCATE. Approve retention and an owner-run expiry procedure separately.

Persist decoded base64 as bytea and the remaining document metadata separately. Use the SHA-256 of canonical full document as receipt_key and insert without overwriting. The broker reconstructs the document from those columns. Its authorizeExactSlot dependency must check worker, authenticated job, READY, lease/cutoff, same context digest, selected LIVE slot and exact race/horse/version. Return an archive lookup and the earlier of lease/cutoff in Unix milliseconds. The broker checks again after reading. A pinned Ed25519 key attests the broker's claim-scoped read. It is a BAKEN operator receipt, never a signature issued by JRA. Check raw hash and pinned parser output separately. Provision a test-only signer for staging and a separately approved key for any production deployment.

Approval order: approve roles, retention and broker runtime; apply table and grants in a transaction; verify grants and canonical byte round trip in staging; approve and enable acquisition hook only; capture an eligible card; verify reader on an authorized existing CLAIM with the pinned parser; connect read-only research observer. Keep normal save guard authoritative. Disable both optional hooks to revert. Preserve already captured archive evidence under the approved retention policy. No connection is enabled by these files.
