## 実装済みの比較契約

`paired-input.mjs` の `registration → freezeInput → runPair → persistBundle`。

- 評価器のソースfingerprint・版、欠損処理、順位定義、EYE方針、結果隔離方針、既知46Rの除外を事前登録する。
- 入力原文のバイト列SHA-256と、決定的JSON正規化SHA-256を分離する。独自のJSON正規化でありRFC8785準拠とは主張しない。
- 両方式へ同じJSON文字列と全ACTIVE馬の同じ馬番・馬ID集合を渡す。馬ID重複、集合欠落、出力ハッシュ不一致、版違いを拒否する。未知順位はnull＋理由のまま残す。
- 取得原文bodyのSHA-256、URL、取得時刻を検査。FUTUREモードではJRA公式ホストを要求するが、ホスト文字列とハッシュだけで公式取得の事実を証明したとは扱わない。
- 事前登録、入力取得、評価固定に対し、登録された公開鍵によるEd25519受領証を検査する。登録＜取得≦固定＜発走、決定証跡＜発走を要求する。署名のないローカル時刻だけで通さない。
- 結果・人気・オッズの既知キーを入力から拒否する。過去走着順と今回結果を区別する。同日以後の過去走は拒否する。
- 原文、入力lock、事前登録、比較ログ、原証跡bodyを新規ディレクトリへ保存する。同名上書きは拒否する。

**署名検査実装と、信頼できる実取得者の接続は別。** テストは生成した架空鍵・架空6頭のみ。実際の証明者・公開鍵の承認と、証明者による全ACTIVE集合・公式原文・正確な時計の確認は未実施。自己署名を公式証拠に格上げしない。ファイルのwxは研究スクリプトによる上書きを防ぐが、OS権限を持つ第三者による改変まで不可能にする保管方式ではない。

評価関数は研究呼び出し口として注入する契約。ソース関数文字列のハッシュは検査するが、外部依存・モデル・隠れたclosure・自由文の意味的リークまで保証する実行サンドボックスではない。将来接続時には完全な依存/モデル/設定manifestの固定と、ネットワーク・結果領域にアクセスできない実行環境の検証が必要。正規MCPや保存ゲートを代替しない。
