# V13：通常旧版を維持した観測型の並走準備

基準：V12 `5f7fea3f18cf737f4db3ee53632e273773753334`、Draft PR #51。今回は本番の再読・CLAIM・保存・DBアクセスを行わず、V12で確認済みのソースを基準にした。新しい採点式・係数・EYE理論はない。

## コードとChatGPT判断の境界

|処理|コード化|ChatGPT/運用側|
|---|---|---|
|入力/候補|認証、CLAIM/期限、履歴結合、BASE_CORE候補|通常業務として対象を確保する承認|
|全頭評価|比較材料・候補順位の提供|各馬の独立評価、S〜F、具体理由、全頭比較、TOP5とEYE判断|
|根拠補正|検証済み追加根拠による既存delta・順位/印再計算|TOP5集合変化時のEYE再監査|
|EYE補完|指定scopeで、提出された正式監査を検査してnull時のみ補完|全候補の根拠/独立性/反証/比較を実際に評価。コードが監査を自動実施するわけではない|
|保存|context再取得、Eval/OWN材料再取得、通常補正、保護付きRPC、FROZEN読取|完成payloadの提出と通常の保存承認|

根拠は`flow-map.json`の固定source hashとV10/V12保存資料。旧版は「現行の正式運用の実出力」を観測する対象であり、手動判断を偽の100点関数にしない。元の完全自動生成器がないことだけを理由に、この観測型比較を設計不能とはしない。一方で実入力と可視判断記録が残せなければ比較不可。

V9の`runPair`は実装関数の同一入力評価を要求する別契約。そこへ手動出力を関数と偽って入れず、V9自体を緩めない。今回は同じraw hash/証拠固定の原則を使う別の観測運用手順を準備した。

## 実装済み

- **[RUNBOOK.md](RUNBOOK.md)**：CLAIM前準備→同一原文の配布→旧版通常評価/保存→独立研究固定→発走後比較。
- `record-archive.mjs`：原文byte列の保管、SHA-256、上書き拒否、ローカル記録時刻の区別、不足条件の表示。JSON payloadを加工せず、visible judgementも元テキストのまま保管する。
- `inspect`はファイル存在/hashチェックまで。時刻証明や実際の入力使用を検証したことにしない。現在は必ず`COMPARISON_NOT_MET`を返し、成功件数を増やさない。
- 資格情報が混じる入力は保管を拒否し、勝手に削除して「同じ原文」にしない。保管失敗で本番を止めるコードはない。

`record-archive`は実体のあるローカル保管補助であり、本番接続済み・WORM保管・公式時刻証明・保存RPC検証器ではない。OS権限を持つ操作まで変更不能とはしない。V9〜V12の証拠/採点ゲートはそのまま。

## 最短の運用上の要点

1. 研究のための新規CLAIMは不要。通常業務で承認された1回のcontextを使う。
2. 旧版は通常の評価/監査/保存を優先し、研究の完了を待たせない。研究だけが未達になる。
3. **保存前の再取得も比較対象情報に含める。** 初回contextだけ同じでも、追加材料が不明なら厳密比較はできない。
4. 統合版だけへ新たな能力情報を補完しない。ID/原文/時計の証明がない履歴は未採用、欠損はnull。
5. 旧版の提出draftと実FROZENを区別する。通常補正を研究の都合で無効化しない。
6. 旧版の順位や実結果を統合評価へ見せない。既存の開発集合loaderを未来入力処理に流用しない。
7. 研究固定は発走3分前と元CLAIM期限の早い方より前。期限後の出力は前向き実証としない。

## 保存物

原文context、protocol、旧版の可視判断/監査、提出payload、実FROZEN、receipt、保存直前の追加入力、履歴証拠、実時刻証明、研究出力を分離保管する。`REQUIRED`にこの10種を定義したが、ファイルが10個揃うことは比較条件の実証ではない。

**実入力・私有情報は承認済み非公開保管領域へ**。研究Gitへ実データを自動公開する機能はない。今回Gitに入れたのはコード・手順・検査記録のみ。認証ヘッダー・claim_token・キーを保管しない。

CLIは新しい非公開研究ディレクトリを指定して使う：

```
node research/unified-engine-20261116/v13/record-archive.mjs init /APPROVED_PRIVATE_RESEARCH_PATH/session
node research/unified-engine-20261116/v13/record-archive.mjs add /APPROVED_PRIVATE_RESEARCH_PATH/session context /EXACT_EXPORTED_CONTEXT.json
node research/unified-engine-20261116/v13/record-archive.mjs inspect /APPROVED_PRIVATE_RESEARCH_PATH/session
```

パスは説明用。実レースファイルを今回作ったという意味ではない。`recorded_at_utc`は書込時刻だけで、元の取得/生成時刻の代用にしない。JSON原文とHTTP元byte列のhash、contextとwrapperのhashを混同しない。
