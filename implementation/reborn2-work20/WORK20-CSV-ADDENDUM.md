# REBORN 2 第1工程 Work20 — NAR日次CSV実ファイル接続

## 結論

実ファイルを読み取る独立・読み取り専用ブリッジを実装した。ZIP原本は変更せず、`racelist` と `horselist` だけを解析し、`payback` は存在確認のみで内容を読まない。人気列、オッズ、払戻、分析対象競走の結果は分析材料へ入らない。

2026年11月28日の実ファイルでは、高知・佐賀の完了済み23競走、240出走行を、将来の対象競走に対する公式過去走候補として接続できた。内訳は完走234行、取消・除外・競走中止6行である。高知12Rは取得時点で結果未完了の12行を含むため競走単位で保留した。ばんえい12競走114行は平地用NORMAL契約の対象外として除外した。

ただし、CSVにはNAR馬固有IDがない。馬名、生年月日、父、母、母父は本人馬照合の候補キーとして保持するが、IDを捏造せず、公式プロフィールIDとのクロスウォークが済むまでは `formal_analysis_ready=false` とする。第1工程は前進したが、まだ合格ではない。

## 実装した境界

- ZIPメンバーの一意性とパストラバーサルを検査
- UTF-8 BOM、racelist 66列、horselist 36列を検査
- 高知・佐賀だけを平地用履歴候補として採用
- 取得時刻が対象競走cutoffより前で、かつ履歴競走日が対象日より前の場合だけ採用
- 数値着順と、取消・除外・競走中止・失格を区別
- 未公表・不明結果が1頭でもある競走は競走単位で保留
- 競走ID、競走条件、出走行を結合
- 競走単位の通過順から馬番別の通過グループを生成
- 括弧内の併走グループを保持し、記号から物理的な着差を推定しない
- 対象競走結果、人気、オッズ、払戻の流入を拒否
- payback CSVの本文は読み込まない
- 原本ハッシュ、取得時刻、ZIP内メンバー名を証拠参照として保持
- 本番、DB、FROZEN、V48分析ロジックを変更しない

## 発走前後の扱い

取得記録は2026年11月28日21:07:34 JSTであり、同日の対象競走に対する発走前材料にはできない。ブリッジは同日20:50 cutoffの試験で採用0件になることを確認した。このファイルは、取得後に行われる別日の対象競走についてのみ過去走候補になり得る。

## 取得できた材料と限界

- 取得: 競走場、日付、R、距離、コース区分、回り、天候、馬場、条件、枠、馬番、馬名、性齢、血統候補、騎手、斤量、調教師、馬体重、着順、時計、着差表記、上がり3F、競走単位通過順。
- 欠損: この実ファイルではハロンタイム全列が空であり、ラップは供給できない。
- 制約: 通過順は競走単位の文字列から馬番を照合したもので、括弧・区切り記号を正確な馬身差へ変換しない。
- 最大の残存ゲート: 公式プロフィールのNAR馬固有IDとCSV本人馬のクロスウォーク。
- 利用条件: 非公開個人研究での一時処理と、原本・派生全行データの再配布可否は分けて扱う。継続取得、原本保存、外部AI処理、公開・商用利用は確認完了まで正式採用しない。

## 再現

```bash
python3 -m unittest -v implementation/reborn2-work20/test_nar_daily_csv_bridge.py

python3 implementation/reborn2-work20/nar_daily_csv_bridge.py SOURCE.zip \
  --acquired-at 2026-11-28T21:07:34+09:00 \
  --target-post 2026-11-29T15:40:00+09:00
```

原本ZIPと全行出力はリポジトリへ保存しない。再現時は権限のある非公開作業領域の原本を明示的に渡す。

## 次の最小工程

1. NAR公式プロフィールから馬固有IDを取得できる許可済み経路を接続する。
2. 馬名・生年月日・血統と公式プロフィールIDを照合し、不一致と同名馬を停止する。
3. 複数日CSV間を固有IDで連結し、対象競走cutoffより前の履歴だけをNORMAL入力へ供給する。
4. ラップ空欄は欠損のまま維持し、別の正規公式資料が確認できた場合だけ補う。

この状態では「CSV競走・出走行の接続」は実証済みだが、「本人馬ID付き全履歴供給」は未完成である。
