# BAKEN LAB | LAB EYE 共通判定基準 (JRA / LOCAL) — 統一仕様案 v1

作成: 2026-10-17 JST  
状態: **開発ブランチのみ / JRA本番未適用**  
範囲: LAB 🧪EYEの選出判定のみ。能力順位・スコア配点は競馬場別ロジックを維持。

## 基本方針

「TOP5外で、**今回のレース条件では能力順位以上に走る可能性**を、具体的な証拠で説明できる1頭（該当なしも可）」。

1. **TOP5能力評価の確定が先**。オッズ・人気は能力順位およびEYE選出に使用しない。
2. **全頭の評価後、TOP5外の全馬を独立再監査**。ランク6自動選出は不可。
3. EYE選出に必要な材料は **最低2種類**。それぞれがすべて以下を満たす:
   - 今回の出走条件・相手関係に **有効**（`current_relevance=true`）。
   - **独立した要因**である。同じ過去レースを言い換えたり、「前走僅差」「前走好走」のように同じ現象を二重計上しない。
   - 具体的なデータ・日付・出所に基づく。出所不明・憶測・単なる可能性をカウントしない。
   - 好転方向が明確で、反証（大敗続き、斤量増、条件未経験、長期休養など）と比較しても有効と説明できる。
4. 2材料を満たす候補がいなければ**該当なし（EYE null）**で保存する。定員・最低選出割合は設けない。
5. 2材料以上の候補が複数なら、データの新しさ・対象条件への直接性・反証の強さを比較し、最も確かな候補を選ぶ。**2つという個数だけで同列に扱わない**。
6. 能力順位はEYEによって変更しない。EYEはTOP5外のみ。選んだ候補について理由とリスクも表示・記録する。
7. 不明な枠順・馬体重・馬場傾向・展開・馬具・騎手効果は **MISSING/未検証** とし、有効材料にカウントしない。

## 例

有効な組合せ例（要・レース個別検証）:
- その競馬場・距離・馬場での具体的好走歴 + **今回実際に相手が弱くなると裏付けられる**クラス・相手条件の緩和。
- 同距離での実走能力 + 今回の確定斤量が過去の比較対象から減り、斤量差が当該レースで有利に働く合理的根拠。

無効な組合せ:
- 「前走4着小差」+「同じ前走の勝ち馬との差が小さい」→ 同一の走りを2回数えている。
- 「当該距離に適性あり」+「当該距離で過去に好走」→ 同一の履歴を2つのラベルにしただけ。
- 「同条件好走がある」+「以前は騎手Aだった」→ 騎手変更の効果未実証なら2つ目に含めない。
- 当日未取得の枠/馬体重/脚質競合を推測 → 根拠ではない。
- 有効1件 + 今回無効1件 → **EYE不可**。

## 実装要件

### LOCAL
既存`CHAPPY_LOCAL_1.6_EYE_FACTOR_COUNT_20261013`を継続。2026-10-17の本番DB migration `local_eye_current_relevance_count_20261017` は、登録数 `jsonb_array_length(...)` でなく `current_relevance=true` の個数を数えるよう修正済み。

ただしDB上の「有効」フラグは**自己申告**。重複・因果独立性・適合性の審査は別途必要。機械判定が通ったことを的中精度の証明にしない。

### JRA
現行`JRA_REBUILD_0.3_FLAT_HISTORY_EYE_ALLCLASS_20261004`はLOCALと異なるJSONと監査形式で、保存関数は2材料の成立を必須検査しない。共通基準の**完成扱いは禁止**。

- JRA独自の能力スコア/クラス/芝ダート評価は維持する。
- 次期JRA EYE監査形式に「TOP5外全頭のレビュー」「2件以上の独立した今回有効な証拠」「不採用理由」「無選出」を導入する。
- 現行JRA保存のプロデューサーとRPCの両方を揃えてテストするまで本番プロトコル切替不可。
- JRA 0.3の既存FROZENを再計算・上書きしない。

## 実施前テスト（JRAの本番切替必須条件）

1. TOP5外全頭の監査漏れは拒否。
2. 独立した今回有効なプラス2件がある候補は受理。
3. 片方`current_relevance=false`なら拒否。
4. 同じ原因を言い換えた重複2件は拒否。
5. 証拠参照なしの材料は拒否。
6. 認定候補なしのEYE nullは受理。
7. 順位6位の自動選出は禁止、TOP5内をEYEとして保存不可。
8. 人気・オッズが評価に使われないことを確認。
9. 既存JRA 0.3の読み取り・HUB表示に影響なし。
10. 正規CLAIM、発走前保存、予想FROZEN不変、ジョブDONEを維持。

## 運用判断
JRA・LOCALを合わせるのは **「何をEYEとして認めるか」だけ**。レース特性や情報入手条件、能力モデルはむやみに同一化しない。明日の保存経路を壊す危険があればJRA本番変更を見送り、テストを続行。

禁止: Cron再開、有料API、既存FROZEN書換、直接予想テーブル更新、保存ガード回避。
