## 2. 毎レース、順位決定より前に実行する順序

1. 公式 READY・現在時刻が発走前・有効な正規CLAIM・未保存を確認。人気、オッズ、対象レース結果を入力しない。
2. 全ACTIVE馬の公式過去走を独立に読み、近走着順・着差の単位・時計・通過順・上がり・級・距離・場所・馬場・斤量・騎手・休養を公式source refsと照合。未確認の全ラップ・不利・調教を推測加点しない。
3. 今回出走馬のうち過去の同一レースで対戦した組を、official_past_content.head_to_head などの公式pre-race事実から抽出。先着／後着、計測可能な時計差、当時の場所・級・馬場、通過位置を比較。前走馬との差を勝ち馬との差と誤読しない。
4. 各比較に対し今回も優位を維持できるのか、距離・斤量・級・展開・近況で逆転しうるのか、肯定・反証の両方を検討。該当直接対戦がなければ NO_VERIFIED_DIRECT_PAIRS と明示し、別の材料で独立評価。
5. **その後に**従来LOCAL1.6の各馬100点評価と1位からの全頭順位を決める。直接対戦の出典が存在する馬は、順位判断への使い方と反証を追跡できるようにする。まだ認証できない点数算術を「機械的に再現済み」と言わない。
6. TOP5と◎の反証比較、5位と6位の境界確認。その後、TOP5外全馬のEYE17項目を監査し、今回条件に現在性がある独立肯定カテゴリ2件以上・最多1頭・該当なし可。6位自動採用なし。
7. 正規ライブCLAIMがあるとき、研究版 lab_rank_repro_preflight の full_field_pairwise_proof / boundary_proof / honmei_challenge / criterion_trace_status を確認。検出された不足は可能な範囲で発走前に再評価。診断があっただけで得点・順位反映や本番保存完了を主張しない。
8. 発走前・公式READY・有効CLAIM・未FROZENを再確認して正規MCPからのみ保存し、receiptと本番FROZENを照合。既存FROZEN変更、直接DB更新、期限切れCLAIMや発走後の保存をしない。

## 4. 時間切れ・欠測・安全

- 「データ取得済み」≠「予想の順位決定へ使用済み」。比較・反証・順位への判断を独立に示す。
- REVIEW_REQUIREDやINVALIDを成功と数えず、妥当な公式出典で解消する。ない資料はMISSING。文章量だけを増やして通過させない。
- 任意の研究監査やその接続不調だけで正規の旧版SAVEを止める変更はしない。本番保存必須化には既存の正規ゲート／タイムアウト／再試行／receiptの安全性検証が先。
- 成績評価は発走後の別経路。16日の結果を過去走資料に混ぜて同日予想を再現しない。精度比較は旧版との前条件一致、検証対象・除外を明示する。
